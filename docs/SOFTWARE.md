# Программный комплекс QL-01.R1

Java 21 + Maven; Spring Boot 3.5.16 зафиксирован в исходниках. Успешная сборка не заменяет аудит зависимостей перед публичным развёртыванием. По умолчанию сервер слушает только localhost.

## Запуск

```bash
mvn -B verify
java -jar software/simulator/target/simulator-0.1.0.jar generated/demo
java -jar software/desktop/target/desktop-0.1.0.jar
```

Запустите сервер в отдельном терминале, задав собственный случайный `QULAY_TOKEN` не короче 24 символов. Примеры для Linux/macOS и PowerShell находятся в корневом README.

```bash
java -jar software/server/target/server-0.1.0.jar
```

Веб-интерфейс: `http://127.0.0.1:8080/`. Есть список обследований, загрузка прохода, простой план и отчёт. REST принимает многообъектный план, но полноценный визуальный редактор карты пока не реализован. Удалённый доступ требует HTTPS и самостоятельного эксплуатационного аудита; не включайте `QULAY_DEV_MODE` для сетевой работы.

Desktop открывает JSON с парным SHA-256, показывает матрицу 31 канала, выбранный продольный профиль и отдельно сырые углы. Сырые углы не подтверждают контакт. Недостоверные участки серые; интерполяция через пропуски не выполняется. Отчёт содержит причины блокировки приёмки. Из приложения можно загрузить проход на сервер, экспортировать CSV координат, получить план по UUID и записать его с SHA-256 в `QULAY/plans` на флеш-памяти. Файловые расчёты и сетевые операции выполняются вне потока Swing.

## Синхронизация и план

```text
java -jar software/agent/target/agent-0.1.0.jar sync SURVEY_DIRECTORY SERVER_URL
java -jar software/agent/target/agent-0.1.0.jar pull-plan PLAN_UUID SERVER_URL USB_ROOT
```

Параметры заглавными буквами заменяются своими значениями. Токен читается из окружения. План сохраняется в `USB_ROOT/QULAY/plans/PLAN_UUID.json` и `.sha256`.

Синхронизация проверяет каждый законченный JSON и отправляет идемпотентный PUT. Старый `.uploaded` не используется как доказательство наличия файла на другом или восстановленном сервере. Повреждённый файл не мешает попытаться отправить остальные; по завершении возвращается ошибка, если хотя бы один файл не отправлен. `.wire.partial` не загружается как завершённое обследование.

## Реальная плата

```bash
java -jar software/agent/target/agent-0.1.0.jar capture /dev/ttyACM0 calibration.json plan.json 1000 /media/usb/QULAY/surveys 10 0
```

Обязательные параметры: порт/файл, индивидуальная калибровка 31 каналов, план с парным SHA-256, число кадров 3…20000, выходной каталог. Необязательные: тайм-аут полного кадра 1…120 секунд (по умолчанию 10), индекс объекта плана с нуля (по умолчанию 0). План должен содержать выбранный объект. `QULAY_DEVICE_ID` задаёт идентификатор прибора; стандартное имя предназначено только для прототипа.

Чтение ограничено 1024 байтами строки ещё до её накопления. Очередь ограничена 16 строками; есть тайм-аут, общий срок захвата и предел числа отвергнутых кадров. Сохраняются исходные строки, включая отвергнутые по CRC/порядку. Частичная последняя строка не превращается в законченный кадр.

При неполном захвате остаётся `.wire.partial`, без готового JSON. Полный проход получает JSON/SHA-256 и `.wire`. Журнал синхронизируется через каждые 100 принятых кадров и при закрытии. При физическом отключении питания/отказе накопителя сохранность последних кадров не гарантируется; это отдельное испытание.

Воспроизведение из обычного файла получает `simulated=true`. Это предохраняет от выдачи лабораторного воспроизведения за новое полевое обследование. Захват через `/dev/ttyACM0` предполагает реально работающий Linux/Pico; тесты в CI не доказывают электрическое подключение физического прибора.

В Q1 нет проверенного детектора усилия/контакта; CONTACT_UNKNOWN сохраняется. Драйверы внешней геодезии, GNSS и конкретного LTE-модема не заявлены как реализованные. Для сети используется стандартное IP-соединение Linux; Wi-Fi/точка доступа телефона достаточны для программного обмена.

## REST v1

| Метод и маршрут | Назначение |
|---|---|
| `GET /health` | Состояние без токена |
| `PUT/GET /api/v1/surveys/{uuid}` | Неизменяемый проход |
| `GET /api/v1/surveys` | Список проходов |
| `GET /api/v1/surveys/{uuid}/report` | Демонстрационная геометрическая оценка |
| `GET /api/v1/surveys/{uuid}/points.csv` | Координаты с масками достоверности |
| `GET /api/v1/surveys/{uuid}/curb-profile` | Анализ площадок вдоль бордюра |
| `PUT/GET /api/v1/plans/{uuid}` | Неизменяемый план |
| `GET /api/v1/plans` | Список планов |
| `GET /api/v1/rule-profiles` | Только демонстрационный профиль в текущей версии |

Загрузка: UTF-8 JSON, `Content-Type: application/json`, `Authorization: Bearer ...`, `X-Content-SHA256: ...`. Те же байты с тем же UUID — успешный повтор; другие — 409; неверный SHA-256 — 422. Сохраняются принятые исходные байты. Предел 32 MiB. Повторные ключи, лишний JSON в хвосте, нецелая версия схемы, неожиданные поля и неявные преобразования строк в числа/boolean отвергаются. Проверяются размерности, конечность чисел и порядок кадров.

Хранилище — локальные каталоги одного процесса с атомарной записью, не кластерная СУБД. Хеш не является электронной подписью оператора. Отдельные роли пользователей, PostGIS, цифровые подписи и промышленная эксплуатационная конфигурация ещё не реализованы.

## Проверки

`mvn verify` выполняет модульные тесты. `tools/e2e.py` поднимает настоящий JVM-сервер и проверяет HTTP, файлы, планы, повторы и перезапуск. `tools/test_summary.py` собирает результат из фактически созданных JUnit XML и E2E JSON. Достоверные идентификаторы сборки находятся в `generated/verification/summary.json`.

Снимок работающего окна с известными тестовыми данными:

```text
java -jar software/desktop/target/desktop-0.1.0.jar --preview SURVEY_JSON --screenshot IMAGE_PNG
```

Это требует графического окружения; CI использует Xvfb. Снимок делается через AWT Robot с экрана, а не рисуется отдельно от приложения. После записи приложение закрывается. Реальный токен в поле при таком запуске не подставляется.

Во всей R1 `acceptanceEligible` блокируется причиной `PROTOTYPE_METROLOGY_NOT_VALIDATED`. Семь синтетических сценариев не являются аппаратной эмуляцией RP2040, аналоговой симуляцией электроники или доказательством точности измерения.
